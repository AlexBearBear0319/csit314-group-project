# UI work

- Read `UI_GUIDELINES.md` before every UI task.
- Use the shared Tailwind theme and components.
- Keep routes, public props, and current behaviour unless an approved story needs a change.
- Do not add business rules or sample records without a source.
- Follow the user's writing and UI rules. Use short text and simple English. When the user asks for ASD-STE100, use common words, short sentences, and active voice.
- Do not add page subtitles, obvious instructions, implementation explanations, or permanent limit notices. Show extra text only when it helps a user make a choice or fix an error. Put optional explanations in accessible tooltips.
- Keep labels, keyboard access, visible focus, contrast, and reduced-motion support.
- State what you changed and which checks you ran. Do not claim a check passed unless it ran.
